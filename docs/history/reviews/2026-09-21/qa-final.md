## 1. Findings

Severity is what the owner would feel on the phone. "Expected" quotes the round-3 item or the PR body.

**1. High — changing a note's language in Details detaches every recording's marker, so "Transcribe again in Malayalam" duplicates the paragraph and Delete recording no longer cuts it.** (T7 × the editor draft.) Expected: the openapi text for `/retranscribe` — the recording's paragraph is replaced where it stands, by its marker. Actual: Details → language Malayalam makes the editor PATCH the whole draft (`{"version":21,"title":…,"body":"<full body>",…,"language":"ml"}`, request captured in `mobile-note-ink-dup.log`). The server treats any `body` in a PATCH as a user edit: `CarryCaptureMarkers` (`backend/internal/service/note_markers.go:76-100`, and the comment at :127 saying so) strips the markers and re-appends them at the end of the body, where each "paragraph" encloses nothing. The retranscribe then appends a second copy and leaves the first; a later Delete recording removes only the marker and leaves the orphaned text. Body before: intro + gutter sentence; after the UI flow: intro + gutter + gutter; after Delete recording: intro + orphaned gutter (`mobile-note-ink-mutate-05-retranscribed.png`, `mobile-note-ink-mutate-07-after-delete.png`). Isolated over the API (`marker-test.log`): file → PATCH the same body plus `language` → DELETE capture → paragraph not cut; file → PATCH the same body → retranscribe → two paragraphs; file → PATCH `language` alone → retranscribe → one paragraph, replaced correctly. So the route is right and the trigger is the frontend sending an unchanged `body` with every field change (language, kind, verbatim, auto_clean all ride the draft). Two one-line fixes, either suffices, both are better: in `CarryCaptureMarkers` keep the markers in place when `StripCaptureMarkers(stored) == StripCaptureMarkers(edited)` (an unchanged body is not an edit), and in `autosave`/`NoteActions` send `body` only when it changed. This predates round 3 in the backend, but T7 is what turned it into visible duplication.

**2. Medium — under a chosen language the "Heard as X" chip can never appear, and re-transcribing the English clip "in Malayalam" landed with no visible change.** (T7/T8.) Actual: after `retranscribe` under `ml` (implicit and explicit `{"language":"ml"}`) `segments.json` says `language: "Malayalam"` while the three segments are byte-identical to the English run (`retranscribe-repro.log`) — Whisper echoes the requested language, so `heardAs(detected, effective)` differs only under Auto-detect, where the fact chip "Heard as English" did show. Also `capture.language` is `null` on the wire after an explicit request although the contract says it is remembered.

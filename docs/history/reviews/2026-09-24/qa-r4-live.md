## Notes and observations (no failures; for the owner's attention)

1. **R4-17 is a release, not a cancel.** PR #97's body says a tab-bar hold "cancels when the page is hidden … through the same path as pointercancel" and round-4.md's fix says `cancel()`. The shipped `useHoldToTalk.ts` (lines ~289–311) deliberately calls `release()` for a `holding` phase ("an interruption yields a partial recording, never a discard") and `onPointerCancel()` only for an armed press. Live: the microphone closed at once and the 1.6 s of audio was uploaded into the note. The defect (mic left open) is fixed; only the wording of the PR body / review disagrees with the code. File: `frontend/src/features/capture/useHoldToTalk.ts`. Method caveat: headless Chromium cannot hide a tab, so `document.visibilityState` was overridden to `'hidden'` and `visibilitychange` dispatched — this exercises the handler, not the OS path.
2. **Text-only row still asks for audio.** Expanding a `has_audio:false` row issues `GET /v1/captures/{id}/download?kind=audio` → 404 (logged as a console error), then `?kind=clean` → 200. `loadCaptureArtifacts` (`frontend/src/features/notes/artifacts.ts:165`) tolerates the 404 by design ("a purged recording is an expected 404") but `Recordings.tsx:749` could pass `has_audio` so the request is skipped. Cosmetic (console noise, one wasted call); R4-24 itself passes. Also worth knowing: a note with a single recording auto-expands it on the Recordings tab — my first tap collapsed it, hence the re-run.
3. **R4-11 cold offline start not verifiable in this harness.** After a page reload with Playwright's network emulation offline, Chromium reports `navigator.onLine === true` (probe `qar4-A11.js`: warm offline → hold selects, PASS; reload while offline → `onLine:true`, hold lifts, ⋮ items enabled). `useOnline()` reads `navigator.onLine`, so the app did what its input said. A real device with no interface reports `false`; recommend a one-off manual check on a phone in airplane mode after a cold start. Shots `qar4-A11-mobile-ink-02/03-*.png`.
4. **R4-23 ×:** `ChecklistPreview` renders `DeleteItem` only for done items, and a fresh proposal has none, so the disabled × could not be observed; the boxes were disabled and the forced clicks wrote nothing.
5. **Console.** The only recurring `console.error` is GitHub Pages answering `/chintan/dev/<route>` with 404.html before the SPA boots — present on every deep link in every run, absent for in-app navigation. Mic runs also log two `requestfailed PUT … ERR_ABORTED` for `peaks.json` and `audio.webm` on S3 alongside successful PUTs (an aborted duplicate attempt; the upload completes and the row files). Neither is new to this round.
6. **Worker speed.** `POST /v1/notes/{id}/clean` and `POST /v1/inbox/text` both landed in ~3 s; a 4 s recording filed (Upload → Transcribing → Filing → Saving) in 5.3 s.

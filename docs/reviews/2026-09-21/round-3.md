# Chintan review, round 3 — 2026-09-21

Nine lenses (backend, frontend, ux, infra, product, security, perf, swipe, lang) reviewed commit `924f0a0` (v0.5.16, live on prod at the start of the run) independently, and two adversarial verifiers then tried to refute and to reproduce every finding. This document reconciles them. Where the verifiers disagreed with a lens, the ruling is stated with both sides. While the review ran, main moved to `5413e4f`: #62 shipped Send-while-recording and round icon controls on the capture screen, and #63 bumped the frontend dependency group with `baseUrl` removed. Findings those two PRs overtook are marked as such rather than dropped, because the residue matters.

Every path is relative to the repo root. Every claim marked ★ was reached independently by two or more lenses before verification. Severity is the reconciler's call and is explained where it departs from a lens.

## 1. Executive answer

Chintan at v0.5.18 is a sound single-user alpha. The Go gates are clean, prod emitted zero WARN or ERROR lines from either Lambda in fourteen days, tenant isolation, JWT verification, CORS, presigned-URL scoping and log hygiene all hold when probed live, the deployed stacks match the templates, and the bill is two percent of a ten-dollar budget. What the owner feels is not rot in the core but three failures at the edges. First, swipe is dead on every touch device since #53, because the `lostpointercapture` handler added for a pen edge case fires when the pressed button hands its implicit capture to the row; a one-line guard fixes it and four lenses reproduced it. Second, multi-language fails for two compounding reasons: a recording made from Home is transcribed in the tenant default before the router picks a note, so a note's language is never applied to the common flow, and the owner's live default is `auto`, under which Whisper re-scripted real Malayalam as Tamil and silently dropped the Malayalam sentence from a mixed clip. The fix is to re-transcribe once after routing in the destination note's language, and for the owner to set Malayalam as the default tonight. Third, the phone UI spends half its pixels on chrome: the note screen gives the body 44 percent of the screen with two record controls 30 px apart, Home puts the first note at 45 percent, and You is three screens long. Section 3 turns that into an ordered list that returns about 130 px to the note body and unifies the menus. Also closing tonight because they are unambiguous: self sign-up is open on the production user pool, the retention field promises a number the server rounds down before deleting audio, and every access token carries a Cognito admin scope nothing uses.

## 2. Findings

Order is by reconciled severity, then by how many lenses converged. "Stream" names the implementation stream in section 7. Effort is S (under two hours), M (half a day), L (more). DO-NOW means the stream implements it tonight; OWNER means it waits in section 4.

### High

**T1 ★ Swipe-to-reveal is dead on touch: the child's implicit-capture hand-over is read as a cancel** — frontend, S, DO-NOW. (FRONTEND-01, UX-1, PRODUCT-2, SWIPE-1; all four confirmed by both verifiers.) On a touch pointer Chrome captures the pointer to the pointerdown target, the inner `<button class="note-row">`. When the drag passes the slop, `useSwipeActions.ts:213` calls `setPointerCapture` on the `.swipe` container; the browser then fires a bubbling `lostpointercapture` at the child, and the handler at `:272-277` (added in e1e11d5, #53, not #56 as one lens wrote) calls `end(event, true)`, nulling the gesture one frame after it committed. Every later move is ignored, `--swipe-x` stays `0px`, and the tray never opens on Home, in the archive or on recording heads; the lift's click then opens the note. The swipe lens bisected it (b055156 opens the tray, 924f0a0 does not) and validated a jsdom regression test that fails at HEAD and passes with the fix. Fix: in `onLostPointerCapture` return early when `event.target !== event.currentTarget`, because a descendant handing its implicit capture to the container is not the container losing capture; the pen-drift case the handler was added for is already covered by `onPointerLeave`. Add the jsdom test (stub `setPointerCapture` to dispatch a bubbling `lostpointercapture` from the inner button mid-drag, assert `data-dragging` and then `data-open`) and the Chromium touch e2e from T31, since jsdom has no pointer capture and no e2e project has touch enabled. Ship this first and alone.

**T2 ★ Recordings made from Home are transcribed in the tenant default; the destination note's language is never applied** — backend, M, DO-NOW. (LANG-2, BACKEND-4, FRONTEND-03; confirmed.) `pipeline.go:379-393` transcribes before it routes, and `transcriptionLanguage` (`:626-651`) reads `note.Language` only when `capture.NoteID` was set at creation, so a Malayalam dictation aimed by voice at the owner's `ml` note is sent to Whisper with the tenant default and the router then matches nonsense. `language_test.go:61` pins this as intended. Notes the router creates get no language at all (`route` calls `CreateNote(ctx, tenant, title, nil)`), so a later "Record into this" also uses the default. Prod confirms the setup this bites: one tenant has default `en` with notes tagged `ml`, the other default `auto` with an `ml` note. BACKEND-4 and FRONTEND-03 left the choice between re-transcribing after routing and a per-recording language control to the owner; the ruling is that re-transcription is the promise the note's "Transcription language" field already makes, costs about four cents per audio hour only in the mismatch case, and needs no new UI, so it is DO-NOW, while the per-recording pill goes to the owner (section 4, item 2). Fix: after `route()` lands on a note whose `Language` is set, not `auto`, and differs from the code actually sent, clear `RawKey`, `SegmentsKey` and `RoutedKey`, re-run `transcribe` with the note's language, re-run the instruction strip with the destination pinned (the `stripInstructions` shape already exists), then continue to `clean`; store the code used on the capture blob so a retry is idempotent. When the router creates a note and the tenant default is a code rather than `auto`, store that code on the new note so it survives a later default change. Extend `language_test.go` with both cases.

**T3 Auto-detect, the owner's live default, re-scripts Malayalam as Tamil and drops Malayalam from code-switched speech; the app's copy recommends it** — product, S, split: copy DO-NOW, setting OWNER. (LANG-1; lens said Critical, both verifiers said High, ruling High because the caveats below are real.) Two caveats from the repro verifier temper the fix: the human clip was isolated words and the `ml` output was still imperfect, and one human-Malayalam-plus-English clip under `ml` lost the English, so "force ml" is a strong improvement rather than a clean solution, which is why T59 (trialling `whisper-large-v3`) sits beside it. Fix tonight: correct the `types.go:126-138` comment, the `openapi.yaml` `default_language` text and backlog row D7, which all call auto "the closest to mixed"; add one hint under the You-screen language row and in the note Details hint: "Mix Malayalam and English in one recording? Choose Malayalam. Auto-detect picks one language per recording and drops or re-scripts the other." Owner: set You → Transcription language to Malayalam (section 4, item 1).

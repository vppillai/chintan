# Owner feedback, 30 Sept 2026 (round 8), verbatim intent

F1. Checklists need more than one level of sub-items (today: one level, deliberately clamped in round 6).
F2. Back navigation feels like a browser: About → Notes → About → Back walks every screen. Want one linear back path that always ends at the main screen, app-like, especially in the installed mobile app.
F3. While editing text with the keyboard up, recording means: dismiss keyboard, then press record. Acceptable, but if a clean minimal option exists (e.g. a small floating record button top-right only in text-editing mode, never masking text), do it. Do not compromise the clean minimalist UI; if no clean way, keep current behaviour.
F4. Swipe between note tabs (Text / Cleaned / Recordings) works as expected, but the animation during the swipe could be better.
F5. PTT is hidden in the About menu. Want WhatsApp-like: the record button acts as PTT by default (hold to talk); slide up while holding to lock into hands-free recording. Need an equivalent clean flow on desktop web too (slide-up is a mobile gesture).
F6. Slide-to-cancel for PTT does not work: pressing PTT always records and sends; there is no way to cancel. Bring a clean cancel to the front flow. "Think thoroughly about how we want to get this done, and then implement it."
F7. PTT as a home-screen feature (the /talk shortcut/widget) is not useful: you must open the app then PTT. A hardware-like push button won't work for a web app. Clean it up.
F8. Now that checklist inputs are split up properly at capture time, is the Split up tab still needed? Or give it a different purpose. Review and update.
F9. Notification banners (filing receipts/notices on Home) look like just another note row. Make them clearly identifiable as dismissible notifications: different theme treatment, custom icons, or similar.

Standing rules: alpha, one user, no back-compat burden, never lose notes. Clean minimalist UI. Tokens-only CSS, both themes, 44 px, reduced motion, a11y.
